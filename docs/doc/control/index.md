# 集控概览

> 集控是 SecRandom 的集中管理端：教室机分散在各个教室时，你在办公室用浏览器就能看到每台设备的状态，并对它们统一操作。

## 它能帮你做什么

- 打开控制台就知道**哪台机器在线**、叫什么、什么版本、多久没上报；
- 需要时远程**锁定抽取、发起一次抽取、重置本轮、播报一句话**；
- 不用走到每台机器前，就能**改设置、更新名单与奖池**；
- 谁在什么时候对哪台机器做了什么，**审计里都有记录**。

不接入集控时，SecRandom 的一切功能照常可用；接入只是多了一层「可以被远程管理、也随时可以退出」的能力。

## 需要准备什么

| | |
|---|---|
| **账号** | 思拓创联账号（官方云）。控制台与设备用同一个账号，没有另外的账号体系 |
| **设备** | 教室机安装 SecRandom v3 桌面客户端；**平板既可以当遥控器，也可以被远程管理**，手机只能当遥控器 |
| **网络** | 设备能上网即可。设备是主动连出的，一般不用改校园网设置 |

## 六步接入

1. **在教室机上登录账号**：用这台机器自己的思拓创联账号即可，**不需要所有机器共用一个账号**。
2. **在控制台建组**：[secrandom-control.sectl.cn](https://secrandom-control.sectl.cn)。组名按**区域**取，例如「教学楼 3 栋 2 楼」「实验楼机房 A」——一个区域一个组，就能管住那里的所有教室机。
3. （可选）**邀请他人**：生成邀请链接发给对方，对方登录后即可加入，角色由你指定；他名下的教室机也能接进这个组。
4. **在教室机上填组 ID**，并打开「允许被远程控制」（设置 → 通用 → 集控）。
5. **回到控制台看节点列表**：设备连上来就会自动出现，显示在线。
6. **试一次**：在设备详情页点「立即抽取」或「禁止抽取」。

::: tip 关键：机器上登录的账号只要「在这个组里」就行
不是必须所有教室机共用一个账号。**每台机器各用各的账号**，只要那个账号**已经是这个组的成员**（你建的组、或被邀请加入的组都算），填上组 ID、打开开关，它就会作为一个节点接入。

反过来说，如果那台机器上登录的账号**不在这个组里**，连接会被拒绝——这时用邀请码把它加入组即可。
:::

::: tip 不需要手动登记设备
设备接入后会自动出现在节点列表里，不用在控制台"添加设备"。列表里没有它，先看设备上的连接状态与提示文字。
:::

## 一条原则

> 远程说了不算，**设备说了算**。

每台教室机都保留自己的开关，关掉后不接受任何远程操作；账号被盗、管理员误操作，都不等于教室机被控制。详见[安全与常见问题](/doc/control/security)。

## 开源与自部署

- **服务端与 Web 控制台已经公开**：[SecRandom-Control-Console](https://github.com/SECTL/SecRandom-Control-Console)（服务端 Elastic-2.0、控制台 AGPL-3.0）。
- **可以自行部署**：把服务端装到你自己的服务器上，设备与数据都在你手里；官方托管只是其中一种跑法，详见[自部署](/doc/control/self-host)。
- **官方镜像可以直接拉**：发布在 GHCR（`ghcr.io/sectl/secrandom-control-console`），服务器上两个文件、两条命令就能起来，不用 clone 源码、不用装 .NET 与 Node；版本号就是**部署日期**，`2026.10.07` 就是 2026-10-07 那一版。
- **设备端实现随客户端公开**：[SECTL/SecRandom](https://github.com/SECTL/SecRandom)（GPL-3.0）。
- 问题反馈：[SecRandom Issues](https://github.com/SECTL/SecRandom/issues)。

> 自部署目前还**不适合正式上线**：服务端与 Web 控制台源码已经公开，但自建登录（本地账号 / 飞书 / 钉钉）还在开发——现在的代码里没有任何身份源，部署出来的实例登不进去。详见[自部署](/doc/control/self-host)。
