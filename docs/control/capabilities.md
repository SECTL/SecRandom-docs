# 远程能力与限制

> 这一页回答两个问题：**每项远程操作需要什么权限**，以及**它为什么可能被拒绝**。

## 能力清单

集控的操作是围绕「**能力（capability）**」组织的：设备在连接时声明自己支持哪些能力，控制台据此裁剪按钮，服务端据此授权，设备据此决定执不执行。

| 能力 | 界面上的说法 | 最低角色 | 说明 |
|---|---|---|---|
| `node.status.read` | 读取状态 | 查看者 | 在线情况、平台、版本、设备名等非敏感状态；所有平台都会声明 |
| `proof.list` | 读取证明列表 | 查看者 | 协议中定义的能力，**当前桌面客户端尚未声明**，因此界面上不会出现 |
| `draw.lock` | 禁止 / 允许抽取 | 操作者 | 「期望状态」：设备离线也生效，上线后自动收敛 |
| `draw.trigger` | 触发一次抽取 | 操作者 | 「动作命令」：立即抽一次，带过期时间 |
| `media.play` | 展示结果 / 播报 | 操作者 | 语音播报；可选择在播报前先在设备上显示结果窗（见下方「播报能带什么参数」） |
| `settings.read` | 读取设置 | 操作者 | 只读，返回设置目录与当前值，**不含任何凭据** |
| `settings.write` | 修改设置 | 管理员 | 仅限设备标记为「可远程修改」的设置项 |
| `roster.read` | 读取名单 | 管理员 | **最敏感的一条只读通道**：名单包含学生姓名 |
| `roster.write` | 修改名单 | 管理员 | 下发点名名单或奖池 |

::: info 为什么「读设置」比「改设置」权限低
看得见和改得动是两件事：使用者应该能看到自己那台机器的配置，改它才需要管理员。
:::

::: warning 没有「远程重启」
协议里曾经规划过远程重启设备，**已被明确否决**：重启教室机等于打断正在上的课，而且远程无法恢复，误操作代价远大于收益。因此**任何界面都不会出现远程重启按钮**。
:::

## 三种命令，三种脾气

| 类型 | 例子 | 过期与离线行为 |
|---|---|---|
| **期望状态** | 禁止 / 允许抽取 | 不是「做一次」，而是「应该是什么样」：设好之后**设备离线也照样生效**，它上线后自动收敛。多次修改以最新一次为准 |
| **动作命令** | 立即抽取、播报、下发名单、改设置 | 带**过期时间**（默认两分钟左右，界面会自动处理）。设备离线时命令会排队，等它上线补投；**若届时已经过期，就直接丢弃、绝不补执行** |
| **查询命令** | 读取设置、读取名单 | 有效期很短（几十秒），过期就不答了——「三分钟后才送到的『现在有哪些名单』没有意义」 |

::: tip 「发送成功」不等于「执行成功」
控制台把命令交给服务端后，还要等设备回执才能知道结果。请在**命令回执**里看状态：排队中 / 已投递 / 设备已接受 / 执行完成 / 设备拒绝 / 执行失败。被拒绝时界面会给出设备说明的原因和下一步动作。
:::

## 设备自己也会拒绝

即使你的角色足够、命令也合法，设备仍可能拒绝。这不是故障，而是设计：

| 设备侧的拒绝 | 含义 | 怎么办 |
|---|---|---|
| **本机开关关着** | 控制台显示「本机已禁用远控」 | 只能到那台机器上重新打开，控制台改不了 |
| **抽取被锁定** | 控制台下发过「禁止抽取」，本机与远程都抽不了 | 在节点详情页点**允许抽取** |
| **设备正在抽取** | 改设置、换名单、再抽一次都会被拒（改配置会让结果与证明对不上） | 等这一轮结束 |
| **需要本机验证** | 该设备配置了密码 / TOTP / U 盘保护，**远程命令不会拉起验证框**（教室机可能没人） | 到设备上操作，或先调整该设备的安全设置 |
| **上课时间限制** | 该设备启用了课程联动，判定现在处于上课时间 | 属于设备本机策略，由设备自己决定 |
| **没有声明该能力** | 设备不支持这项操作 | 界面通常会直接隐藏按钮 |
| **命令过于频繁** | 设备自带限流（默认约 10 秒内最多 20 条，会告知具体数值） | 稍后重试，不要连续猛点 |
| **命令已过期** | 命令在路上耽搁太久，或设备离线期间就过期了 | 重新下发 |

## 哪些设置不能远程修改

以下内容**永远不在远程白名单里**，设备会直接拒绝——能远程开自启、改安全策略，等于把设备所有权交出去：

- **安全设置**（密码 / TOTP / U 盘、按操作验证策略）
- **集控自身的设置**（本机开关、组 ID、节点身份）——这些不住在普通设置里，控制台根本读不到也改不到
- **桌面集成**：开机自启、后台常驻、启动窗口、URL 协议注册
- **更新设置**
- **备份设置**、**证明留存期**
- 窗口置顶方式、以及各类协议「已同意」版本

可以远程修改的主要是**抽取与通知相关**的设置（默认抽取、点名、闪抽、抽奖、语音、通知、外观、浮窗、联动、更多设置等分类，以设备实际标记为准）。

::: tip 两类标记不要混淆
- **不可远程修改**：设备明确说这一项不能改，控件置灰；
- **未读取**：设备没上报这一项的值，不代表不能改。

另外，设置下发是**全有或全无**：混进一个不可写的项，整条命令都会被拒绝。
:::

## 数据与体积限制

远程下发与回传都要装进一帧，因此有体积上限：

- 名单**较大时只会回传一部分**并标记**已截断**（读取本身也有限额：最多 50 份名单 / 奖池，每份最多 500 人，且不分页）；此时界面会提示改用「只增改」，因为「整份覆盖」会把没回传的人删掉；
- 一次导入的名单行数有上限（当前 2000 行），超出会拒绝并提示；
- 设备设置过多时会**按分类分批读取**；连单个分类都读不回来会明确报错；
- 播报正文**不超过 200 字**，设备本机可能还有更严的限制（被拒时会告知）。

## 远程抽取能带什么参数

| 抽取方式 | 说明 |
|---|---|
| **快抽** | 不传任何参数：设备按自己的闪抽默认名单抽 1 个 |
| **点名单** | 可指定名单、性别、分组、人数；**只作用于这一次下发，不改设备上的默认设置** |

- 性别与分组的可选项**来自读取回来的名单成员**，不会凭空写死「男 / 女 / 第一组」；
- 人数上限由**名单里符合条件的人数**决定，超出会被设备拒绝并告诉你实际区间；
- 控制台会用已读到的名单做一次**本机预检**，提前发现「没人可抽」「条件不存在」「人数越界」等情况；
- 抽取结果会随回执返回（抽到了谁、名单、人数），显示在节点详情页的「最近一次抽取」里。

## 播报能带什么参数

| 参数 | 说明 |
|---|---|
| **正文** | 不超过 200 字，用**那台设备本机的语音引擎**播报；正文不会写进日志 |
| **显示闪抽窗口** | 开关，默认关闭 |
| **系统音量 / 播报音量** | 0–100，二选一：**「不修改」**（这次别碰它）或**「设定为」**（临时改，播报结束后恢复原值）。注意 `0` 是「设为静音」，是一次真实改动 |

批量播报会逐台下发，正在抽取的机器会拒绝，界面会报出失败设备。
