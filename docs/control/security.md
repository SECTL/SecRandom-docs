# 安全与隐私

> 集控的服务端由官方托管，**目前不开源**。因此正确的态度不是「相信它」，而是：**把它当作一个可能被攻破的组件**，把真正的安全边界放在你看得见、摸得着的地方。

## 四条设计前提

官方把这四条列为集控的**设计前提**（不是加分项）：

1. **权力在设备手上**——任何改变设备行为的操作都必须能被**设备本地授权拒绝**；账号权限只决定「谁能下发」，不决定「设备必须接受」。
2. **下发内容必须签名**——策略与名单包需经签名校验后才应用；「我是服务端」本身不构成信任。
3. **命令必须可过期**——动作型命令带过期时间，过期即丢弃，**绝不补执行**。
4. **可断连、可审计**——设备可本地一键断连且断网生效；全部远程操作留审计记录。

::: warning 这四条是承诺，不是你能自行审计的实现
服务端不开源，你无法核对这些设计是否被不打折扣地实现。因此实际使用中，请以**你能验证的部分**为准：本机开关、设备上的行为、控制台里的审计记录。
:::

## 安全边界到底在哪

```
控制台（界面）  →  服务端（判定权限）  →  设备（最终权威，可以拒绝）
```

- **界面裁剪不是安全边界**：按钮是否显示只是易用性，真正的角色判定在服务端执行；
- **服务端也不是最终权威**：服务端只能「拒绝下发」，不能强迫设备执行；
- **设备是最终权威**：本机开关关着时，无论谁下发什么，都不执行。

### 设备上的那个开关，服务端改不了

「允许被远程控制」这个开关：

- **只由设备自己上报**，控制台与任何接口都无法把它打开或关闭；
- 关掉之后不但**不建立连接**，即使收到命令帧也**一律拒绝**；
- 它**不住在普通设置文件里**（而在 `data/config/control/node-state.json`），因此**导入设置或恢复备份不会把远控悄悄打开**。

### 「期望状态」与「动作命令」的区别

- **禁止 / 允许抽取**是**期望状态**：它会被记录下来，设备离线也照样生效，下次上线自动收敛；
- **立即抽取 / 播报 / 改设置 / 下发名单**是**动作命令**：带过期时间，过期即丢弃，**不会在设备上线后突然执行**。

::: tip 关掉本机开关时，之前下发的「禁止抽取」也不再生效
抽取锁定的闸门只在「允许被集控」时起作用。这是有意的：**收回远控权 = 收回所有远程约束**。
:::

## 账号与会话

- 集控**没有独立账号体系**：身份完全来自**思拓创联账号**，不需要也不提供单独的注册与密码；
- 控制台是「浏览器 + 服务端会话」的形态：**浏览器只保存一个不透明的会话标识**，思拓创联的访问令牌保存在服务端，不进入浏览器脚本；
- 会话会定期回思拓创联复核：**在官网退出登录后，控制台这边的会话也会随之失效**（存在一个复核间隔，不是瞬时）；
- **组就是权限边界**：不属于某个组时，控制台对该组**看不到任何内容**（连「这个组是否存在」都不会告诉你）；
- **权限变更立刻影响后续下发**：角色被调整或被移出组后，下一次下发就会被服务端拒绝，不需要通知设备。

### 危险操作都有二次确认

- **立即抽取**：按钮需要**连点两次**（第一次进入待确认状态，几秒内不动作会自动复位）；
- **移除节点 / 批量移除**：确认框明确写出「这不能阻止这台机器再次接入」；
- **移除成员**：确认框说明「该账号立刻失去本组的全部权限」；
- **播报**：不直接下发，先打开「播报选项」对话框确认内容与音量。

## 审计：所有人都被记录

- 记录内容覆盖：建组 / 改名、成员邀请 / 加入 / 改角色 / 移除、邀请创建 / 撤销、转让请求 / 确认 / 拒绝 / 超时、节点登记、策略下发；
- 每条记录包含时间、事件、对象、明细、**操作人**、**来源设备**（浏览器会话 / App 端）与结果；
- **被拒绝的越权尝试同样留痕**（结果为「被拒绝」）；
- **审计只对管理员及以上可见**，可按事件类型、结果、时间范围、来源设备、被操作设备、操作者筛选，并**导出 CSV**；
- 审计**不记录凭据、令牌或学生姓名**，明细里只放可公开的短字符串（例如角色名、拒绝原因码）。

::: info 关于「来源设备」
审计会区分「在电脑上操作」与「在手机上操作」——手机是被借走、被解锁风险最高的设备，这个区分在事后追查时很有用。
:::

## 数据与隐私

### 设备会上报什么

连接期间，设备持续上报的是**非敏感状态**：节点 ID、组 ID、平台、版本、能力清单、本机开关状态、显示名称，以及已应用的策略版本。**班级名等教学信息不会上报。**

### 学生姓名只在你主动读取时才会回传

- 名单**不是**持续上报的数据：只有具备**管理员及以上**角色的人点击「读取设备名单」时，设备才会把名单（含学生姓名）回传给你这次操作；
- 读取时默认**不含已停用的人员**，避免误把停用的人当成「已删除」；
- 抽取结果的回执**只带学号与姓名**，不带其他成员字段；
- **远程播报的正文不会写进日志**，只记录长度。

::: warning 请谨慎对待名单导出
控制台支持把名单导出为 CSV。导出文件落在你的电脑上，之后就与集控无关了——**请按学校的个人信息管理要求存放与销毁**。
:::

### 给管理员的两条建议

- **不要**把学生姓名、教室全称之类的隐私信息写进**节点 ID** 或显示名：审计会长期保留它们。显示名建议用「301班讲台机」这种不含个人信息的写法；
- 需要长期留档时**定期自行导出审计 CSV**：审计记录的保留周期目前没有对外承诺。

## 你可以做的自我保护

| 你想做的事 | 怎么做 |
|---|---|
| **立刻收回远控权** | 到那台设备上关闭「允许被远程控制」（断网也生效） |
| **让某个账号彻底进不来** | 在组成员列表里**移除该成员**（移除节点只是清理登记记录，不是拉黑） |
| **撤销整台设备的登录态** | 在设备上退出思拓创联账号，或在官网退出登录 |
| **换掉组的管理者** | 由创建者发起**转让**（双方确认后生效） |
| **查清「谁动过什么」** | 组详情页 → **审计日志**（管理员及以上可见） |
| **把不同教室的人隔开** | 分成多个组：不同组之间互相看不到 |

## 使用时请避免的误解

- ❌「服务端是官方的，所以它可信」——服务端不开源，且是**可能被攻破**的组件；真正的边界在本机开关与组角色上。
- ❌「点下发的按钮就等于执行了」——要等**命令回执**，被拒绝时界面会说明原因。
- ❌「管理员权限就等于能控制设备」——角色只决定「谁能下发」，设备仍可拒绝。
- ❌「自建一套服务端」——协议公开、服务端实现目前不开源，**官方尚未提供自建方式**。
